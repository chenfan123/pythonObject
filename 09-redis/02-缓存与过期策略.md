# 缓存与过期策略

### TTL 的返回值：

- -1 key 存在，但没有过期时间
- -2 key 不存在
- > =0 剩余 TTL 秒数

### KEEPTTL 的作用

覆盖值，但保留当前 key 剩余的过期倒计时。
`SET cache:product:42:detail:v1 '{"name":"Keyboard","price":79}' KEEPTTL`

- 重新开始生命周期 → SET + EX
- 保持原有生命周期 → SET + KEEPTTL

为什么数据更新建议删缓存呢？

> 相比直接更新缓存，删除缓存不要求写路径同时维护复杂的缓存序列化、字段拼装和 TTL；缓存可以由读路径统一重建。

- TTL：控制缓存最长存活/最长陈旧时间
- DEL：业务数据变更后尽快废弃旧缓存
- 缓存：通常是可重建副本
  写数据库成功 → 删除相关缓存 → 后续读取回填最新缓存
